# Faheem Dehalvi personal site: source

Static, buildless output. Python 3 standard library only. No installs, no CDN, no external fonts, no client-side JavaScript.

Status: local draft. Nothing here has been deployed, pushed or registered anywhere. No hosting is claimed or assumed.

## Layout

```
build.py                  zero-dependency build script
source/
  site.json               all homepage copy, projects, links (edit text here)
  content/working-note.md the one real page of writing that exists today
  templates/*.html        page shells; workflow.svg is the inline hero illustration
  assets/                 styles.css, favicon.svg
tests/                    unittest suite; fixtures are test data, never published
dist/                     build output (regenerated by build.py)
```

## Build

```
python3 build.py
```

Options:

| Flag | Effect |
| --- | --- |
| `--articles-dir DIR` | Import every `*.md` in DIR as an article under `writing/<slug>/`. |
| `--base-url URL` | Adds `canonical`, `og:url`, `sitemap.xml`, `robots.txt` and `mainEntityOfPage`. Without it none of these are written. |
| `--out DIR` | Output directory (default `dist/`). The script refuses to clean a directory that is not empty and not a previous build. |

With no `--articles-dir`, the site lists no articles. The writing section shows only the working note, labelled as such.

## Importing the two reviewed blogs

1. Put the final Markdown files in one directory, for example `../2026-11-11-personal-brand/` once reviewed.
2. Each file needs a title. Either a first line `# Title`, or front matter:

   ```
   ---
   title: Exact article title
   description: One sentence for the list and meta description (optional, derived from the first paragraph if absent)
   slug: short-url-slug (optional, defaults to the filename)
   published: 2026-11-20 (optional)
   draft: true (optional, skips the file)
   ---
   ```
3. Run `python3 build.py --articles-dir <that directory>`.
4. `published` must be an actual publication date in `YYYY-MM-DD`. Only when it is present does the page show a date and emit `datePublished` JSON-LD. Without it, no date appears.
5. Titles in the list, page heading, `<title>` and navigation all come from that one title field, so cards stay accurate after import. A file with no title fails the build instead of guessing one.
6. Slugs `working-note`, `assets` and `index` are reserved. Duplicate slugs fail the build.

Supported Markdown: headings (`#` becomes `h2`, up to `h4`), paragraphs, bullet and numbered lists (one level), fenced code, blockquotes, horizontal rule, `[links](url)`, `**bold**`, `*italic*`, `` `code` ``. Raw HTML is never passed through: everything is escaped first, and only `http`, `https`, `mailto` and relative or `#` links are kept. Anything else (for example `javascript:`) is dropped to plain text. Images are not supported.

## Checks

`build.py` verifies the built tree after every run: `lang="en-AU"`, title, meta description, exactly one `h1`, the `#main` skip target, unique ids, every internal link, asset and `#anchor` resolving to a file, and no scripts other than JSON-LD. It lists every external URL so they can be checked by hand. Exit code is 0 only if all pass.

```
python3 -m unittest discover -s tests
```

The tests cover markdown escaping, unsafe-link removal, the no-articles build, and an import build with `--base-url`.

## Preview and hosting steps

Serve `dist/` over HTTP from its own directory, for example `python3 -m http.server 8000 --directory dist`. Links use directory paths such as `writing/`, so opening files directly with `file://` will not resolve them.

`dist/` is plain files and can be copied to any static host. Links are relative, so it works at a domain root or under a sub-path. Notes for whichever host is chosen:

- `robots.txt` is only honoured at a domain root. If the site lives under a sub-path, the generated one is not used by crawlers.
- `404.html` uses absolute paths based on `--base-url`'s path (or `/` if omitted). Pass `--base-url` for sub-path hosting so the 404 page keeps its styles.
- The build does not choose a domain, create a repository, or publish anything.

## Content rules in force

- Homepage line is the verified one: "I build AI tools for business workflows and explain the decisions behind them."
- No portrait, screenshots, metrics, logos, testimonials, prices, availability or booking links.
- No email address or contact form. Contact is LinkedIn and GitHub only.
- Each project row states what is upstream and what is Faheem's. FD CODE's description follows its repository README and the site makes no performance claim.
- No Intelligent Resourcing architecture, client details, outcomes or benchmarks. The employer link is its public about page.
- JSON-LD is `ProfilePage` with a `Person` (name, two verified `sameAs` URLs, the tagline), with no employer, ratings or awards.

## Known limits

- Browser QA at 320, 375 and 1280 px has not been run by this build. Static checks only.
- External URLs are not fetched by the build.
- The `FD CODE` summary is taken from the supplied verified facts, not re-read from the repository README.
